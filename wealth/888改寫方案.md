## 理論與實作對照

1. **Markowitz 組合理論**：用共同曝險與相關性思考分散，不只數 ETF 檔數。現階段加入成分重疊檢查；不憑單一報酬數字畫效率前緣。參考：[Markowitz Nobel Lecture](https://www.nobelprize.org/uploads/2018/06/markowitz-lecture.pdf)。
2. **資產配置與再平衡實務**：保留使用者的 30% 衛星上限，但將「無條件賣出」改為「啟動再平衡檢視」，要求核對市值、分母與成本。30% 不是學界公認最佳解。參考：[Investor.gov](https://www.investor.gov/introduction-investing/getting-started/asset-allocation)。
3. **績效衡量**：TWR 適合分離外部資金流影響，XIRR 反映金額與時點對投資人報酬的影響；都需適合的資料。單一百分比不具備年化、含息、期間或基準定義。參考：[CFA Institute](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/rates-and-returns)。
4. **決策過程與結果分開**：以決策前檢查、失效條件與覆盤原文取代隨機名人語錄。原頁多筆語錄缺少可核對出處，改成有來源的方法說明；個人日誌全文保留，不代表系統認可其中每項敘述。

## Google Sheets 下一階段資料契約

以下是擴充規格，尚未建立分頁、授權或接入程式。先確認欄位意義，再建立資料端點；不要直接公開含帳號、金額、身分資料的整份工作簿。

### holdings：持倉快照

每列＝某估值日的一個獨立部位。建議欄位：

`as_of, position_id, ticker, name, strategy_bucket, asset_class, currency, quantity, price, market_value_local, fx_to_twd, market_value_twd, target_weight, price_as_of`

- `strategy_bucket` 明確區分 core／satellite／hedge／cash，與資產類別分開；長債不可直接視為現金。
- 006208 與 0050 可能有大量共同曝險；需基金同日成分權重才能量化重疊。
- 同一快照所有金額先換算為 TWD，確認匯率日期；總和需與券商淨資產勾稽。
- 現金是否納入 30% 的分母、避險部位如何處理，必須在策略設定明確定義。
- 可解鎖：自動比例／門檻、策略與資產類別雙視圖、集中度、再平衡差額；成分資料充分後才增加穿透曝險。

### valuations：績效與估值

每列＝同一頻率的組合估值。建議欄位：

`date, portfolio_value_twd, external_flow_twd, flow_timing, unit_nav_total_return, benchmark_total_return_index, benchmark_id, risk_free_return`

- 若以單位淨值衡量，需正確處理現金流、費用與股利；不要用市值成長率代替報酬。
- TWR 遇到外部流入／流出需要適當分段估值或明確揭露近似算法。
- 最大回撤以調整現金流的累積報酬或含息淨值計算；有匯款時直接拿資產金額算回撤會失真。
- 基準需對應策略、相同日期及幣別並使用含息口徑。夏普比率需共同頻率、無風險利率與適足樣本；揭露年化方法及觀測數。
- 可解鎖：累積報酬對基準、回撤曲線、滾動波動、適當定義的風險調整績效。資料不足時保持 unavailable。

### cashflows：外部現金流

`date, cashflow_id, type, amount_twd, note`

以投資人角度定義投入為負、提領為正，加上估值日的期末資產正值計算 XIRR。帳戶內股利再投入及買賣不重複記為外部現金流。處理沒有正負號變化、無解或多解時的異常，不強行輸出數字。

### settings 與 journal 擴充

- settings：策略版本、生效日、目標權重、再平衡上限、分母政策、交易成本估計、檢視頻率。
- journal 保留原四欄；可另加 `decision_type, hypothesis, evidence_url, invalidation_rule, review_due, review_outcome`。提醒目前是文字包含「提醒」的規則，不能等同正式到期提醒或交易訊號。

## 禁止 Google 搜尋索引

HTML head 已加入 robots 與 googlebot 的 `noindex, nofollow, nosnippet, noimageindex`。不加入搜尋用結構化資料或 sitemap 項目。

- **不要只在 robots.txt Disallow /wealth/**：Google 必須能抓取頁面才看得到 noindex；只封鎖抓取可能留下網址索引。現有站點 robots.txt／sitemap 尚未更動。
- 若頁面已被索引，部署後以 Search Console 網址檢查確認 noindex，必要時申請暫時移除；不能承諾即刻從搜尋結果消失。
- noindex 不是登入保護。公開 GitHub 原始碼、CSV 和 Google 發布圖表仍可被直接讀取。
- 若真正目標是只有本人可看，需另外使用具驗證的主機與資料 API、撤銷 Sheets 公開發布並清查 GitHub 公開歷史。不能用前端密碼或把 URL 藏起來代替授權。

參考：[Google noindex 說明](https://developers.google.com/search/docs/crawling-indexing/block-indexing)、[Robots meta tag](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag)。

## 技術取捨與部署

- 延續單一 HTML，可完整取代指定頁面；不增加框架、套件管理或第三方圖表 CDN。CSS 僅在此獨立文件，不修改其他頁面或共享樣式。若未來改為嵌入既有頁面，需再將 CSS 加命名空間。
- 動態資料一律用 textContent 建立節點，避免把 Sheets 文字當 HTML 執行；CSV 支援 BOM、CRLF、引號、逗號、跨行文字。
- 兩個 CSV 各自處理成功／失敗，15 秒逾時，防止同步重入。保留本頁上次成功值時明確標示尚未更新，不落地缓存財務資料。
- 原始跨來源 iframe 不讀取內部 DOM；提供外開連結。原圖本身的 3D、固定尺寸與字級由 Sheets 控制；若手機內部圖形裁切，需在 Google 圖表端改版，或有持倉資料後改用自製 2D 圖表。
- 交付 HTML 中沒有硬編碼真實資產金額；試算初始為空值。GitHub Pages 正式網域的 CORS、CSP 與 Google 發布設定仍需部署後確認。

部署時只替換 `wealth/index.html`；不要把本方案或測試腳本放上公開站點。部署後再检查正式網址的 CSV 成功狀態、圖表、行動版及 noindex。此交付尚未 commit、push 或部署。
